## 2. Hacker News（Show HN）

标题：
`Show HN: Android app that audits your own Wi-Fi passphrase, on-device`

正文：
```
I kept seeing Android "Wi-Fi cracker" apps that were either wrappers around a
paid API or flat-out lying about success. So I built the opposite: it associates
every candidate for real from a rooted phone (`su` + `cmd wifi`), and it refuses
to report success unless three signals appear on the same supplicant line —
SSID, state COMPLETED, and a valid IP.

The interesting constraint is that Android connects to one network at a time, so
trying a huge wordlist is measured in days. That pushes the design toward
generating a few hundred likely candidates from the SSID, vendor OUI, house
number, name, birthday, phone number, and sorting them, rather than brute force.

Secondary paths: WPS PIN (including half-handshake / Pixie-dust style checks),
offline .cap/.hc22000 verification, and post-connection LAN recon. Apache-2.0,
fully offline, root required. Feedback on false-positive cases especially welcome.
```

时间：美东周二～周四 08:00–10:00 提交。

## 3. Reddit r/netsec（技术帖，不要营销腔）

标题：`On-device WPA/WPA2 passphrase auditing on Android: what it takes to avoid false positives`

正文骨架（配判定链示意图 + 三条证据的真实日志截图）：

- 问题：关联成功 ≠ 密码正确（WPA2/WPA3 过渡、同名 SSID 多 AP）
- 方案：三条同源证据（SSID / COMPLETED / 有效 IP），缺一即「不确定」
- 代价：手机串行关联，候选质量 > 数量
- 数据：18 个目标 / 107 次真实命中，哪些口令形状从未出现
- 附带：WPS 判据 `km=WPS`/`WPS-M2D`，离线校验 1 万条 37 秒
- 结尾放仓库链接 + 明确「只对自有/授权网络」

r/netsec 只看技术可信度，**不要**在标题里放 "free"、"crack" 字样。
