# 无 Root + Shizuku 真机验收方案（2026-11-20）

> 本文档给**用户本人**执行。我不代做真机测试，也不改变你的网络状态。
> 每一步都写了「预期结果」与「异常时怎么取证」。

## 0. 前置条件

| 项 | 要求 |
|---|---|
| 设备 | **真正没有 Root** 的 Android 设备（不是关掉 su 授权） |
| Android | 11 及以上（`connect-network` 需要 11+；13+ 更稳） |
| Shizuku | 已安装，用**无线调试**启动（不是 root 启动） |
| APK | `/data/local/tmp/wpf-shz18.apk`<br>sha256 `8db33b8a92239d56f0b4e7322b126296ab80e6f2980ee99f3a1214a65ddd8f51` |

**关键：必须确认 Shizuku 是 shell 身份启动的。** 判定方法见 §1。

## 1. 环境自检（做任何测试前先过这一关）

1. 装 APK，打开应用 → 设置页
2. 看「当前环境」卡片

**预期：**

```
运行模式        rootless
Root            不可用        su 无输出或未授权
Shizuku         已授权（shell 身份）      ← 必须是 shell，不是 root
Android         13 (API 33)
设备 / ROM      <你的机型>
最近检测        HH:MM:SS
```

**如果 Shizuku 显示「已授权（root 身份）」→ 停。**
说明 Shizuku 是 root 启动的，这台机器**不能**用来验收「纯无 Root」场景。

**取证方法：** 长按设置页那行状态 → 弹出完整检测证据 → 截图。

## 2. 能力矩阵核对

设置页「功能能力」卡片逐项看：

| 能力 | 期望（Android 13 + shell Shizuku） |
|---|---|
| cmd wifi status | 可用 |
| cmd wifi connect-network | 可用 |
| cmd wifi forget-network | 可用 |
| wifi_connect（在线验证） | 可用，依据里写「通道=Shizuku」 |
| 系统已保存网络 | **不支持**（SELinux 拦 shell 身份）← 这是正常的 |
| supplicant 日志 | 未知 或 不支持 |
| WPS PIN | 不支持（需 root） |

**注意：**
- 「系统已保存网络」不支持**不影响破解判定**（净检走 forget-network + 回读）
- 若 `wifi_connect` 显示**灰色「未知」**→ 探测没拿到结果，不是设备不行。
  长按状态行看证据里的 `basis` 与 `raw`。

## 3. 在线验证真机测试（核心）

### 3.1 准备

1. 目标：**你自己拥有或明确获准测试的 AP**
2. 在系统设置里「取消保存」该网络（否则系统可能用旧口令连上）
3. 准备一个**已知正确**的密码，和一个**已知错误**的密码

### 3.2 测试 A：正确密码

1. 观测页 → 选目标 AP
2. 破解页 → 选一本只含该正确密码的字典（或用「连接自测」直接输入）
3. 开始

**预期：**

```
已验证成功   1        ← 绿色
已证实错误   0
未确定       0
通道         Shizuku   ← 计划行显示的通道名
```

日志里应出现：
```
⚡ 密钥命中：候选#N（证据: supplicant+netId 或 supplicant · 尝试 <runId>-N）
```

**如果显示「已验证成功 0 / 未确定 1」：**
说明拿到 CONNECTED 但归属不足（AT2）。这时看日志里的
`前提不足(...)` 或 `netid-conflict` 字样 —— 那是**正确行为**
（宁可报未确定，不可报假成功）。取证：导出日志。

### 3.3 测试 B：错误密码

1. 换成已知**错误**的密码
2. 开始

**预期：**

```
已验证成功   0        ← 必须是 0
```

**绝对不允许出现「已验证成功 ≥1」。** 若出现 → 立即停止并导出日志，
这是必须修的假阳性。

### 3.4 测试 C：旧连接污染

1. 先手动连上目标 AP（系统里连着）
2. 不改任何东西，直接跑一个**错误**密码

**预期：** 应该是 `UNKNOWN`（"目标已连着，无法归因"）或
`STALE_CONFIG` 闸门拦下，**不是 SUCCESS**。

### 3.5 测试 D：连续两次

1. 先跑正确密码（命中）
2. 立刻跑错误密码

**预期：** 第二次不能因为"上一条连着"而报成功。
代码里有 `disconnectAndVerify` 与 `attemptId` 严格相等两道防护。

## 4. Shizuku 状态变化测试

### 4.1 运行中停掉 Shizuku

1. 跑一个较长的字典任务
2. 中途去 Shizuku 里「停止服务」

**预期：**
- 日志出现「Shizuku 服务已退出（Binder 断开），请重新启动服务」
- 任务不会继续假装在用 Shizuku
- 统计里这些条目进 `环境错误`，不是「密码错」

### 4.2 运行中撤销授权

1. 同上，但去 Shizuku → 应用管理 → 关掉 WPAForge

**预期：** 日志出现「Shizuku 授权已失效…请重新授权」，同样进环境错误。

1. 关掉「显示在其他应用上层」权限

**预期：**
- 不崩
- 日志出现「悬浮窗未授权，已跳过（改用应用内状态展示；不影响破解任务）」

## 7. 已知不能达到的能力（不是 bug）

| 能力 | 原因 |
|---|---|
| 系统已保存网络的原始配置 | SELinux 拦 shell 身份读 `/data/misc/apexdata/.../WifiConfigStore.xml` |
| supplicant 日志 | 部分 ROM（如 ColorOS）根本不输出该 tag，root 也读不到 |
| WPS PIN | 需要向 supplicant 控制口写命令，非 root 无通路 |
| 后台保活加固 | appops / 电池白名单写入需要 su |

这些**都不影响在线验证与成功判定**。
