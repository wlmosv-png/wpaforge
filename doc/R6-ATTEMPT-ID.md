## 1. 它要修什么

R3 审计的三条主问题，根子上都是**「这条证据属于谁」无法表达**：

| 审计项 | 现在的归属手段 | 缺什么 |
|---|---|---|

## 2. ID 形状

```
runId     = <秒级时间36进制>-<目标SSID sha256前8>-<进程内序号36进制>
            例：m5k3p1-3f9a2b7c-1
attemptId = runId + "#" + 序号（1 起，与判词里的字典顺序号同源）
            例：m5k3p1-3f9a2b7c-1#11
标记行     = WPF_PROBE|attempt=<attemptId>
```

设计取舍：

- **不含明文**：时间用 36 进制、SSID 只留哈希前 8 位 → 日志/队列/导出里出现 ID 不泄露网络名与口令（测试 `R6-C6` 钉住）。
- **有界**：`MAX_LEN = 64`，异常输入被拒而不是撑爆日志。
- **不抛异常**：非法输入一律 `false` / `-1` / `null`，调用方必须显式处理「无法解析」，不允许异常打断判定流程。
- **`seqOf` 非法返回 `-1` 而不是 `0`**：`0` 会被下游误当成有效序号。

## 3. 生成契约

| 规则 | 内容 | 测试 |
|---|---|---|
| C1-a | `runId` 由「任务启动时刻 + 目标 SSID + 进程内任务序号」决定，**确定性**（同输入同输出，便于复现） | `R6-C1` |
| C1-b | `seq` 从 **1** 起，0 与负值被拒 | `R6-C1` |
| C1-c | 同一次 run 内 `seq` 严格递增、不重复、不复用 | `R6-C1` |
| C1-d | 同秒 + 同 SSID + 同 ordinal 的极端情形也必须给出不同 `runId`（`adoptForResume` 内部兜底 `ordinal+1`） | `R6-C5` |

## 4. 传递契约

| 规则 | 内容 |
|---|---|
| C2-a | 一条候选的 `attemptId` 在 `tryOne` **之前**生成，之后**不可变** |
| C2-b | 它随 `Attempt` 一起回传：逐条结果、最近判定尾巴、任务日志、异常日志都要带上（**接线时逐处核对，本阶段未做**） |
| C2-c | 广播 watcher 需要维护「当前活跃 `attemptId`」（收到广播时取值）；日志读取需要判据 `AttemptMarker.isolated` |
| C2-d | **不得**把 `attemptId` 写进用户可见的结果文案（它含时间与哈希，属内部标识） |

## 5. 失效契约

| 规则 | 内容 | 测试 |
|---|---|---|
| C3-a | 不同 `runId` 的 `attemptId` **永不相等**，即使 `seq` 相同 | `R6-C3` |
| C3-b | 旧 run 的证据**不得**被新 run 引用；跨 run 的 `sameRun` 恒 `false` | `R6-C3` |
| C3-c | 进程被杀 → 内存里的旧 `attemptId` 随之失效；**没有**「用旧 ID 继续用」的路径 | `R6-C5` |
| C3-d | 日志窗口的失效由标记决定：`AttemptMarker.isolated == false` → 该候选的**日志类证据一律不可用**（不是「失败」，是「无证据」） | `R6-C8` |

## 6. 恢复契约

| 规则 | 内容 | 测试 |
|---|---|---|
| C4-a | 断点续跑 / 进程重启 → **开新 run**，`newRunId != previousRunId`（绝不复用） | `R6-C5` |
| C4-b | `previousRunId` 原样保留为**血缘**，只用于事后追问，不再用于任何新证据 | `R6-C5` |
| C4-c | `resumeFromOffset` 原样带出；负值归 0（不猜、不丢） | `R6-C5` |
| C4-d | 首次启动 `previousRunId == null` 必须安全 | `R6-C5` |
| C4-e | 恢复**不得**把旧 run 的判定结果当成新 run 的证据（旧结果只能作为「历史」，状态仍需在新 run 里重新确立） | 契约条文，接线时由 R7 消费 |

## 7. **误用禁令**（最重要的一条）

**`attemptId` 相等 ≠ 底层连接归属成立。**

- 它能回答：这条证据**记在谁名下**、这段日志窗口**属于谁**、这条候选**有没有被尝试过**。
- 它**不能**回答：这条连接**是不是这条候选造成的**。
- 后者仍需独立证据：目标配置已删净并回读、命令前已断开、握手完成属于目标 BSSID。
- 实现上把它固化成一个恒假的哨兵：`AttemptId.attributionProvenByAttemptIdAlone()`。任何「用 ID 代替归属判定」的写法都必须显式写下这一行才通得过评审，而它的分支永远不可达。

同理，日志起点标记只能证明**窗口边界**，不能证明窗口内的连接归属。因此：

> **日志证据可用（`isolated == true`）是「可以看这段日志」的必要条件，不是「可以据此判负」的充分条件。**
