# 未验证路径的安全验证计划（隔离测试网络）

> 目的：把上一轮仍标 **NOT RUN** 的三项在**不触碰任何重要网络**的前提下补齐验证。
> 原则：**不破坏、可回滚、可重复**；不使用家里/公司正在用的网络做破坏性测试；不跑大规模候选。
> 现状：以下三项**尚未真机验证**，任何文档都不得写成"已验证"。

## 0. 前置条件（三条都要满足才动手）

| 前置 | 要求 | 怎么确认 |
|---|---|---|
| 隔离目标 | 一台**专用测试 AP**：手机热点、旧路由器、或临时开的热点均可。SSID 用明显标识（例：`WPFTEST-1`），**不要用你日常连的网络** | 在设置里确认目标 SSID 不是常用网络；记录它的当前口令 |
| 原始状态留档 | 记录测试网络的当前状态：SSID、口令、是否已保存、当前是否连着它 | 手机设置里看一眼；或应用内「本机已存 WiFi」页，**先截图/抄下口令**（这是回滚依据） |
| 最小测试集 | 只准备 3~5 条候选的字典（例如 `00000000`、目标正确口令、`12345678`），**不要跑大字典** | 应用内「加载字典文件」选一个小文件 |
| 环境 | Root 可用；电池优化已加白名单（设置页「一键修复」）；电量 > 30% | 应用内设置页自检 |

**明确禁止**：不要把你的真实已保存网络的配置当作测试对象；不要在别人家的网络上跑；不要为了制造
"进程被杀"而刷机或断电。

## 1. 「用原口令重建」分支（恢复机制里唯一未验证的写回路径）

**为什么它没被覆盖**：上一轮的真机 A/B 用的是**虚构 SSID**（不存在的目标），走的是"无需还原"与
"失败留痕"两条分支；真正"用原口令把配置加回去"必须有一个**真实存在且已保存**的目标。

| 阶段 | 操作 | 预期结果 |
|---|---|---|
| 1 | 让手机**先连上** `WPFTEST-1` 并确认它已被系统保存（能自动重连） | 已保存；`cmd wifi list-networks` 里能看到它 |
| 2 | 在应用选这个目标 + 最小字典（含正确口令），开跑 | 日志出现「配置恢复登记: 目标 WPFTEST-1 · 原 netId=… · 原口令已加密保存 · 快照 OK」 |
| 3 | 跑完后**故意点「暂停」**（不跑完），或让它跑完未命中 | 收尾出现「收尾恢复…」→「配置恢复结论: …」 |
| 4 | 看结论行 | 期望：`已恢复：OK`（读回确认已连上目标）；若为 `原配置已写回但未观察到连上` → 属于**可见故障**，检查网络后手动重连 |
| 5 | 独立复核（不看应用） | 断开再连 `WPFTEST-1`：**能自动连上**说明配置与口令确实正确；若需要重新输口令 → 记录为失败现场 |

**失败时的回滚**：应用会在失败时把候选残留删净（可见故障，不会静默留错口令）。
人工恢复：设置 → WLAN → 找到 `WPFTEST-1` → 忘记网络 → 重新输入你**事先记录**的正确口令。
随后把 `Queue` 里这个任务移除即可。

## 2. 恢复执行**途中**进程被杀

| 阶段 | 操作 | 预期结果 |
|---|---|---|
| 1 | 同上先连上 `WPFTEST-1` 并保证已保存 | —— |
| 2 | 开跑，跑 3~5 条后在**收尾恢复之前**立刻 `am force-stop io.github.wlmosv_png.wpaforge`（或开发者选项里"不保留活动"+强停） | 应用被杀 |
| 3 | 立刻用 root 看 `files/restore.json` | 期望 `stage=ARMED`（记录已落盘，进程没来得及收尾） |
| 4 | 重新打开应用 | 期望日志出现 `recovery(app-start): …`，记录被清除（成功）或转 `FAILED` 且带原因 |
| 5 | 复核 | 同 §1 第 5 步（断开重连能否自动连上） |

**回滚**：同 §1。若记录停在 `FAILED`，可在设置页导出日志并保留现场，再手动重连。

## 3. 连接自测端到端

| 阶段 | 操作 | 预期结果 |
|---|---|---|
| 1 | 仍用 `WPFTEST-1`；先确认它已保存、能自动重连 | —— |
| 2 | 设置页 → 连接自测 → 填 `WPFTEST-1` + **正确**口令 | 报告应出现【保护】已登记 → 各步骤 →【还原】`已恢复：OK`；且断开重连仍能自动连上 |
| 3 | 再跑一次，填**错误**口令 | 同上，收尾仍应还原成功；结论区显示"未握手完成" |
| 4 | 再跑一次，中途**点掉对话框返回桌面**（模拟中断） | 收尾仍执行（finally）；重开应用后若记录还在，启动补做会处理 |
| 5 | 故意制造"登记不到"：开跑前把 `/data/data/<包名>/files` 设为不可写（`chmod 500`）后跑一次 | 期望**拒绝执行**并给出原因码，且**没有**任何改配置的命令被执行；测完记得 `chmod 700` 复原 |

**回滚**：与 §1 相同；`chmod` 那步务必复原（否则应用写不了任何文件）。

## 4. 记录与判定

- 每一步都记录：**时间、命令或操作、实际观察、期望值、结论（PASS/FAIL）**。
- 只要 §1 第 4/5 步通过，就可以把「用原口令重建」从 NOT RUN 升级为**真机已验证**，
  并在发布说明里相应删掉那条已知限制。
- 若任一步失败：保留日志、`restore.json` 现场、当时的 `cmd wifi list-networks` 输出，
  作为缺陷报告，不要自行"修好再说"。
